# 研报价值评估

把评估写成有依据的判断：报告是否可信、增加了什么、对目标读者有多大帮助。评分是透明的比较工具，权重是本框架的约定，不是经过实证校准的客观尺度。

## 1. 确定用途与比较条件

先确认或从请求推断读者、用途、待支持的决策、报告版本与日期、评估时点、已收到的材料。能合理推断就说明假设并继续；用途未知时使用 `balanced`，不擅自假设投资或买卖目的。

阅读 [rubric.md](references/rubric.md) 的判据和 [profiles.json](references/profiles.json) 的权重。按主要用途选择：

| profile | 用途 |
|---|---|
| balanced | 通用质量评估，或用途尚不明确 |
| orientation | 行业入门、全景扫描、求职准备 |
| investment | 投资研究、交易或企业尽调 |
| technical | 学术、技术路线和方法调研 |
| strategy | 企业战略、采购、产品或进入市场决策 |
| publication | 客户交付、公开发布、对外传播 |

同一轮横向比较必须使用同一个权重版本、profile 和评分锚点；不得看完结果再改权重以得到期待的排名。若用途不同，分别计算、分别排名，允许排名反转并解释原因。多用途先报主用途，再按需给副用途敏感性；不擅自平均。用户自定义权重时，在评分前记录理由，十项齐全、非负、总和为 100，并对同批报告统一应用。

此 skill 是独立的用途评分协议，不沿用其他写作 skill 的固定八维分数。跨协议的历史分数不可直接比较；比较时用本协议重新评分，不修改原始历史记录。

## 2. 先检查底线，再讨论总分

按会改变核心结论的重要性选择待核查命题。5–10 个关键数字可用于初筛，不是全文核实凭证。对影响决策的支点，应核对原始记录、口径与计算；观察多处异常时扩大检查或限制评估结论。

- `pass`：在实际检查范围内未发现需限制使用的重大问题；不能表述为全文保证。
- `restricted`：关键输入未核实、重大冲突未解，或已确认的局部错误使特定结论不能使用；标明具体范围和修复条件。
- `reject`：已确认的重大编造或系统性证据、计算、推理失效，破坏报告核心用途；不让其他维度的高分抵消。不将其作为决策依据，诊断分数仅供修复。
- `undetermined`：材料或核查不足以作出底线判断。缺少附件、打不开链接不是确认造假。

按影响范围处理，不因一个非关键笔误否决全文。区分事实错误、口径差异、过时信息、合理分歧与未核实状态。底线状态必须有核查依据；发现具体问题记录报告位置、实际核查、严重性、影响范围、可修复条件及主要扣分归属。

## 3. 按十维评分，显式保留完整性与工具

十维及锚点见 [rubric.md](references/rubric.md)。每项用 0–5 分，允许 0.5 分；贡献分 = 该项分数 / 5 × 当前用途权重。时效性归证据质量，诚实性与边界意识看它是否实际约束证据、推理和结论，不因免责声明数量加分。

论证可读性是研究能否被理解与使用的实质维度。检查读者能否重建“问题 → 结论 → 关键证据 → 推理 → 限制与行动”，不能只看文字通顺、页数、配色或字体。该项以理解成本和解释质量为主，文件与版式可用性为辅；具体检查见 rubric 的“论证可读性”一节。读不懂关键判断时，不因资料齐全而给高分；写得顺畅也不能抵消事实底线问题。

v1.1.0 提高各用途的可读性权重。新旧协议分数不能直接比较；仅更换权重得到的是敏感性分析，不是完成了新的可读性评审。若重新评定原始分数，要记录具体段落的理解障碍或改善，另存新记录，不改历史结果。

每个评分都要对应具体观察和可定位依据，说明加扣分理由。评分无法支持时记 `null`，不记零，不按已评维度重新归一化；只给已评贡献、未评权重和数学可能范围，暂不提供确定总分或完整排名。没有做应做的研究且正文已证实遗漏，可以低分；只是评审没有收到材料，则标为未评估。

重要缺陷指定一个主要扣分维度，避免重复扣分。另记它对决策与底线的影响，不再自动减总分。确有不同损害时可分开扣分，但须分别举证。

## 4. 核查纪律

评估具体命题，而非给来源名称统一排序。公司公告可证明公告与披露，不能单独证明疗效、到账或盈利；同行评议不等于独立复现；多个网站转述同一材料仍是一个证据源。记录被谁观察、怎样产生、能支持什么。

分别说明原始出处核对、计算复算、独立印证、实验复现、页面视觉检查、外部同行评审做过哪些。引用、API 查询、成功运行、哈希或结构校验不能替代事实和推理核验。不得声称检查过未取得的原文、图表或附件；不虚构访谈、访问或专家背书。

对市场、财务、技术和临床比较，核对时间窗、币种、分母、样本选择、对照、资源投入与结果定义。先识别不可比性，再考虑是否可统一；不能为填表硬编市场规模、成功率、概率或目标价。

区分报告发表时质量与今天是否仍适用；明确数据截止日和改变结论的新事件。检索新事件可以检查现时有效性，不得用发表后才出现的信息倒扣其当时准确性。

## 5. 交付评估与可复用记录

默认用用户语言给出：用途与权重 → 底线状态及依据 → 十维分数、贡献及理由 → 最有价值的发现和最影响结论的问题 → 适用范围、评估置信度、优先修复建议。横评时加同口径比较表；近似分数不足以确定胜负时说明，不把 0.1 分当作实质差异。

评估置信度为高/中/低并说明关键命题核查范围、材料缺口和争议；它不同于报告作者结论的置信度，也不是统计概率。没有核查的事实只能作文本层评审，不包装成事实审核。

需要复用、批量比较或核对计算时，使用 [scoring-record.md](references/scoring-record.md) 和脚本。简单对话可用等价表格，不强制生成文件。

```bash
python3 scripts/score_report.py init --profile investment --output /absolute/path/evaluation.json
python3 scripts/score_report.py score /absolute/path/evaluation.json --output /absolute/path/score.json
```

脚本仅校验评分记录并计算分数，不自动评定报告真假、分析水平或底线。`reject` 无可用于排名的总分；`restricted` 的完整分数也必须与使用限制同时呈现。

## 6. 购买价值仅在需要时另评

质量、用途匹配与价格分开。需要估价时说明币种、单次或持续服务、个人或团队授权、独占性、底层数据与访谈等权益。默认个人、非独占、一次获取；比较合法免费替代资料、经核实的增量、实际节省的工作和时效。主观愿付价格不是观察到的市场成交价，不按质量分数机械换价，不把一份报告估成定制咨询服务。确认重大编造时，不推荐为其决策用途付费。
