# 出版一致性工具

在定稿前后使用。`scripts/publication_checks.py` 使用Python标准库，输入保持原样，输出写入新文件。它负责连续引用、声明数值的显示舍入及上下文核对，并给出审读提示。主编继续检查推理、语义重复、限制是否必要、资料分工及最终页面。

## 1. 用稳定来源ID生成出版引用

作者正文先用 `[S01]`、`[S19]` 等稳定来源ID引用。ID支持字母后接数字；输入为UTF-8正文导出，包含表格和图注，来源列表由构建器另行生成。来源目录为JSON数组，每条至少有 `id`、`title`，通常也有 `url`、定位与日期。用户指定作者年份等引用体系时，使用相应实现并保持映射可追溯。

```bash
python3 scripts/publication_checks.py prepare-references --sources source_catalog.json --body body_with_ids.txt --output-dir publication-new
```

输出 `citation_map.json` 与 `numbered_body.txt`。映射按首次出现顺序连续编号；正文保留同一来源的重复引用，来源目录及内部ID保持原样。未使用来源单独列出；未知引用、重复ID或混用已编号正文会提示修复。构建器用该映射的 `number`、`source_id`、`title`、`url` 生成正文链接和文末来源列表。研究内容变化后从稳定ID正文重新生成，而后重建文档。

## 2. 从同一快照生成数字并声明展示精度

构建器可以导入 `format_value(value, decimals, percent)`：十进制 `ROUND_HALF_UP`，输入推荐十进制字符串。选择适合证据和用途的位数，关键比率由未舍入金额先计算。其他引用规则或源披露舍入方式按原意标明并使用相应实现。

数值记录示例（合成的展示一致性示例，数值键连接实际计算快照）：

```json
{
  "values": [
    {
      "id": "residual_growth",
      "kind": "growth_pct",
      "inputs": ["151.987", "264.220"],
      "shown_inputs": ["151.987", "264.220"],
      "decimals": 2,
      "display": "73.84%",
      "context": "残余收入增长73.84%"
    }
  ]
}
```

`number` 的输入为 `[数值]`，`share_pct` 为 `[分子, 分母]`，`growth_pct` 为 `[旧值, 新值]`；比率的原始与展示输入均先统一单位。`display`为数字与可选百分号，单位及期间保留在正文及数值快照中。`context`取实际导出文字中的唯一、足够具体的邻近短句；多个重要重复位置分别登记。程序检查所给数值和上下文，作者核对输入来源及清单覆盖。

若读者看到的输入为 `152.0` 和 `264.2`，展示比率会有尾差。可以增加金额精度；或在相关比较旁写明“百分比按未舍入金额计算”，并在记录中以 `rounding_note` 保存这句原文。检查器同时检查说明确实出现在所提供的正文；主编确认它位于读者需要处。已说明的舍入差异保留为警告，错误的原始计算或显示值仍按错误处理。

## 3. 检查实际导出内容

从最终DOCX／PDF导出正文、表格与图注文字，保持阅读顺序，在来源列表前截取，执行：

```bash
python3 scripts/publication_checks.py check --body final_exported_body.txt --references publication-new/citation_map.json --numbers display_values.json --output publication_review-new.json
```

程序检查编号连续、正文首次出现顺序及映射覆盖、残留稳定ID、声明显示值的舍入及上下文、展示输入能否复算比率。支持逐个 `[1][2]` 标签；合并区间或其他引用风格由等价实现检查。导出引入空白时，数值上下文比较折叠空白。构建器继续检查实际超链接目标与文末来源；PDF提取和最终渲染分别核对。

相同长段落、反复出现的通用提醒及脚本/JSON/本机路径等产生有位置的审读提示。检查者判断其用途，把生产记录移入资料包，保留解释研究对象需要的技术内容。改写同义重复可能没有提示；内容审读仍需执行。

退出码：0为所提供项目机械检查通过，1为发现出版一致性错误，2为输入或文件错误。输出总是将编辑状态标为 `manual_review_required`；缺少数值记录时明确标为尚未检查。结果支持指定输入的检查，来源真实性、数字清单完整性、阅读理解及逐页版面分别给出依据。
