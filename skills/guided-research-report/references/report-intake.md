# 研报类型、范围与大纲确认

## 类型与用途分别选择

类型决定“研究什么、覆盖到哪里”；用途决定“为谁解决什么选择、哪部分值得更深”。向用户提供与主题相关的简短选择卡和推荐理由，通常一轮即可收齐关键信息。

| 研报类型 | 适合的问题 | 建议覆盖与典型产物 |
|---|---|---|
| 行业全景 | 这个行业如何运行，机会和风险在哪？ | 定义、需求、产业链、付费市场、路线、商业模式、竞争、政策、资本、兑现证据、概率展望与尽调行动 |
| 公司研究与尽调 | 这家公司的技术和商业价值靠什么成立？ | 业务引擎、产品和权利、客户证据、分部财务、现金、可比组、关键风险；数据适合时给估值与敏感性 |
| 技术或学术调研 | 哪条路线适合特定任务，证据和复现条件如何？ | 任务、方法、数据、基线、资源、外部有效性、失败模式、复现或验证方案 |
| 企业战略与采购 | 自建、采购、合作或进入哪个市场？ | 买方预算、工作流、替代品、实施成本、权利和切换成本、方案比较、试点验收与行动条件 |
| 专题深度 | 某个明确争议或事件意味着什么？ | 已确认核心问题所需的背景、比较、证据、机制、边界与结论；章节随问题配置 |

主要用途选择 orientation / investment / technical / strategy / publication；希望综合观察时可选择 balanced。客户交付或公开发布可作为任一内容类型的交付要求。例：“AI制药行业全景＋行业入门为主＋对外交付为副”。

## 首轮选择卡

1. 复述主题和请求里已经明确的选择。
2. 推荐一种类型和主要用途，附一句理由；同时给出两三个真正相关的替代组合。
3. 确认读者、地区、信息截止日、深度和输出格式中的关键缺项；把能从上下文合理推断的值直接写入推荐卡。
4. 用户可通过编号、自然语言、修改某项或授权自主选择作答。记录最终组合和依据。

**示例问法**：“这份AI制药报告建议选行业全景，主要用于行业入门，并按正式交付标准排版；也可选投资尽调或技术调研。你希望采用哪种组合？”

提问简洁，已有选择直接沿用。用户只说“帮我写一份AI制药研报”时，先展示推荐卡取得类型与用途选择。用户说“你自行选定类型和大纲，直接完成”时，记录 `confirmation_basis: user_delegated` 并继续。一次小范围改写使用原有已确认范围。

## 范围约定与资料侦察

选定类型后，写明标题承诺、核心问题、必要比较、地区与时间、交付物、资源约束。以有限原始资料侦察判断大纲是否可执行；范围以解决选题和识别关键缺口为度，完整研究在大纲确认后开展。可以告知哪些部分预计采用有依据的区间或透明假设。

## 大纲确认卡

提供适量的章节，使用户能清楚决定是否符合期待：

- 拟定标题、核心问题、暂定回答与信息截止日。
- 各章的读者问题、研究任务、关键比较、拟用证据与图表。
- 行业全景的完整地图，或专题范围的取舍理由。
- 相较常见公开资料预期增加的核验、可比化、解释或工具。
- 关键缺口、条件估计、交付格式和研究包约定。

以一句明确的确认请求收尾，例如：“请确认这份大纲，或指出希望调整的章节；确认后我按这个范围完成研究与写作。”

记录状态：`type_selected → outline_proposed → outline_confirmed → researching → drafting → verified → delivered`。每项保留真实的用户答复、已获批方案或授权来源；`outline_proposed` 表示等待确认。用户明确授权自主拟纲直写时，可记录大纲和 `confirmation_basis: user_delegated` 后推进。已有批准大纲记录 `confirmation_basis: prior_approval`。状态记录可放在工作笔记中。

## 研究推进中的调整

初始大纲表达研究问题和暂定解释；证据决定最终结论。章节次序、局部标题、结论变化按证据更新并记录。改变研究对象、主用途、地区时间范围、核心覆盖或交付承诺时，提供修订及影响，取得用户确认后推进依赖该变化的工作。保留其他已授权且独立的工作。
